# ComfyUI 服务器部署套件（无 GPU / API 客户端模式）

你的服务器没有 GPU，ComfyUI 只当「节点画布 + AI 反代客户端」用：
生图请求走你配置的 API（New API / Gemini / Grok 等），本机只跑界面和节点逻辑。

## 文件

```
(仓库根目录)
  deploy.sh    一键部署脚本（交互菜单 + 非交互参数）
  Dockerfile   CPU 版 PyTorch 镜像（无 CUDA，省 ~4GB）
  .dockerignore  构建只带 requirements，不把 data/ backups/ 打进构建上下文（传服务器别漏了这个点文件）
  workflows/     内置工作流（16 个，文件名 `*.app.json`：每个都是 ComfyUI 的「应用」，打开就是应用界面——右栏填、点运行、中间看结果；按任务归并：同一任务的不同引擎 / 模式放进一个工作流，顶部下拉切换），
                 按类别放在子目录里（1-图片 / 2-文案与配音 / 3-视频），部署时保持子目录铺进 ComfyUI，已存在的不覆盖、有差异会提示（`--refresh-workflows` 才覆盖，先备份）；文档里按编号 01~16 称呼
  custom-nodes/  本套件自带并自己维护的插件和节点（启动容器前铺进 data/custom_nodes；`pro-*` 已存在也会同步成仓库版本，旧版先备份；relayapi 不覆盖，有差异提示）：
                 ComfyUI-relayapi（第三方插件的拷贝，含本地修改，见其 UPSTREAM.md）、pro-gemini-music、pro-poster（海报提示词 / 海报文案拆分）、
                 pro-ali（阿里生图/改图/配音/多角色对白配音/听写/写提示词/音色设计/声音克隆/音色管理）、pro-video（视频配音合成/取音轨/字幕生成/烧字幕/图片轮播）、
                 pro-image（促销标签叠加 / 商品抠图 / 图层合成）、pro-flow（模式 / 选择分支 / 开关门：一个工作流里选引擎和模式；应用界面文字结果）、
                 pro-chat（AI 工作台：说一句话排好几步、每步设置都能改、一键跑完、结果自动传给下一步，见「AI 工作台」一节；没有节点，只有前端大窗口和四个后端接口）
  assets/        随套件铺进 data/input 的素材（无背景音乐.wav：08/10/11 默认 BGM，静音占位；请上传视频.mp4：11 里「上传视频」节点的占位，
                 ComfyUI 提交前会校验所有连着的节点，包括没选中的那一路，所以占位文件必须存在）
  tools/         gen_workflows.py：workflows/*.app.json 的生成脚本（改模板改这里，再 python3 tools/gen_workflows.py）
                 batch_run.py：按 CSV 批量跑任意工作流（见「批量跑」）
```

## 怎么用（在服务器上）

```bash
git clone https://github.com/zxc1136111473-ui/pro-cui.git && cd pro-cui   # 在服务器上
bash deploy.sh                    # 交互菜单
bash deploy.sh --install -y --port 8188   # 一条命令装完
```

装完访问 `http://服务器IP:8188/`。

## 菜单功能

```
1) 全新安装 / 重新部署（容器只有一个，换目录会替换现有这套）
2) 更新到最新版（先预览新提交和风险，确认后 git pull + 插件更新 + 重建镜像 + 重建容器）
3) 体检（访问地址、torch 是否 CPU 版、前端等 comfy 包版本和源码要求是否一致、源码是否在分支上）
4) 改监听端口
5) 配 HTTPS + 访问密码（复用香水商城 Caddy，公网只走域名）
6) 插件管理（汉化 / APIimage / relayapi / 自定义 / 检查插件依赖）
7) 数据说明（源码在哪、怎么改代码、怎么接反代）
8) 一键备份（data/ 含插件/工作流/出图 + 配置 → backups/，只留最近 5 份；可选不含出图）
9) 一键恢复（先校验备份包；端口和绑定方式保留本机当前的，本目录原来没配置时沿用备份里的）
10) 卸载（a 保留目录 / b 连目录删，backups/ 也会删）
11) 测试反代（容器 → New API 连通 + 令牌能用哪些出图模型）
12) 回到上次更新前（更新后运行出问题时用，按旧依赖重建镜像）
13) 空间占用（出图 / 上传 / 工作流 / 插件 / 备份 / 镜像各占多少，只看本项目）
l) 看日志（最近 200 行 / 实时跟随 / 只看本次启动的问题）
s) 同步自带节点 / 工作流到运行中的 ComfyUI（git pull 套件后用；节点有变化才重启，不重建）
w) 把内置工作流换成仓库版本（先备份旧文件，不删）
r) 重启容器（docker restart，不删容器，约 1 秒）   R) 重建容器（删了重新 run）   0) 退出
```

几个会改变实际行为的数值写在 `deploy.sh` 开头：探测超时 5 秒、日志轮转 10MB×3（只作用于这个容器）、
备份保留 5 份、更新预览每个仓库显示 3 条提交。要改先想清楚影响。

重启、重建、更新、恢复、改端口、改绑之前，会先看有没有任务在跑：有就提示「重启会丢掉它们，已发给 New API 的请求照样计费」，
默认不继续（`-y` 照常执行）。要重建镜像的（更新、回退、重新部署），构建完、删容器前会再查一次：
这时取消，镜像和代码都退回旧版，旧容器不动。
`--check` 在容器没跑或页面不通时返回非零（`--json` 的 ok 为 false），外部监控可以直接调。

**没有终端时**（cron、`ssh 主机 命令` 不带 `-t`、`nohup … &` 后台）：每个提问都按默认值走，默认「否」的不会执行，
所以有风险的更新、有任务时的重启、卸载都会自动取消（日志里能看到「没有终端，按默认」）；要强制执行加 `-y`。
没有终端时也进不了菜单，要用参数指定动作（`--update` / `--sync` / `--refresh-workflows` / `--check` / `--backup` …）。

## 核心设计（为什么这么做）

1. **官方主仓库，不拉分支。** 源码 git clone 到 `app/` 并挂载进容器——
   - 改代码：直接编辑 `app/` 下文件 → `docker restart comfyui` 生效，不用重建镜像
   - 更新：菜单 2（git pull 源码和插件 + 重建镜像，新版依赖才装得上）
   - 加功能优先用**插件**（custom node），不要改源码，更新不冲突

2. **数据目录全部挂载**（`data/`），容器重建不丢：
   - `data/models/` 模型文件（走 API 不需要；本地推理就放这）
   - `data/custom_nodes/` 插件（git clone 进来 = 安装）
   - `data/output/` 出图、`data/input/` 上传参考图
   - `data/user/` 网页里保存的工作流、界面设置、Manager 配置（一键备份会带上）
   - 从旧版套件升级：旧的出图、上传图、工作流还在 `app/output`、`app/input`、`app/user`，挂载后界面里看不到，需要的话手动搬：
     `cp -an app/user/. data/user/`（output / input 同理），再菜单 r 重启

3. **CPU 版 PyTorch 镜像**：无 CUDA，省 ~4GB 体积和显存需求。

4. **插件**（菜单 6 一键装，导入所需依赖已预装进镜像；例外：essentials 的抠图 / LUT / 像素化 / Seam Carving 节点缺 rembg 等依赖，不可用）：
   - 1 必备：`ComfyUI-Global-Translation`（汉化）、`ComfyUI-APIimage`（OpenAI 兼容出图/改图/局部重绘）、`ComfyUI-relayapi`（gemini 走 chat 出图，也能出视频）
   - 2 工具：`rgthree-comfy`（组静音、只跑选中输出、图片对比）
   - 3 可选：`ComfyUI-Custom-Scripts`、`ComfyUI_essentials`、`ComfyUI-VideoHelperSuite`
   - 不再预置：`ComfyUI-Logic`（已归档，核心自带 Switch/And/Or/Not）、`ComfyUI-Impact-Pack`（依赖本地模型）。已装的用菜单 6 → 7 卸载
   - 菜单 6 → 6 列出时带 `*` 的插件本地改过文件（例如汉化插件的开关会写它的 `config.json`）。
     更新时会自动暂存、拉完放回；和上游冲突时改用上游版本，你的改动留在该插件目录的 `git stash` 里（需要 git 2.33+，Ubuntu 22.04 起满足）

5. **ComfyUI-Manager 已内置**：官方改成 pip 包（版本跟 ComfyUI 源码里的 `manager_requirements.txt`），
   启动带 `--enable-manager`，不再 git clone；旧的 `custom_nodes/ComfyUI-Manager` 会被自动跳过，可以删掉。
   以 0.0.0.0 监听时（默认 `network_mode=public`），网页 Manager **装不了任何插件**（Registry 的也不行），
   只能更新 / 禁用 / 卸载已装插件和重启；装插件用菜单 6。确实要在网页里装，把 `data/user/__manager/config.ini`
   的 `network_mode` 改成 `personal_cloud`（等于任何能访问端口的人都能装插件）。
   **别用网页 Manager 的「更新 ComfyUI」**：它会把源码切到某个 tag（不在分支上）且不重建镜像，变成新源码配旧依赖，
   之后菜单 2 也拉不动。更新一律走菜单 2；体检（菜单 3）会查出这种情况。

6. **CPU 版 torch 锁死**：镜像用 `PIP_CONSTRAINT` + `UV_CONSTRAINT`（Manager 默认用 uv）锁住 torch / torchvision / torchaudio，
   插件依赖要求别的 torch 版本时会直接报错，不会悄悄换成几 GB 的 CUDA 版。
   新插件有 pip 依赖时：菜单 6 → 8 按镜像查缺哪些包、会改哪些已装包的版本（只看不装），写进 Dockerfile 后菜单选 1（回车保持原设置，只重建镜像、不拉代码）。
   菜单 1 / R / 2 / 4 / 5（改绑时）/ 9 / 12 都是删掉容器再新建，现场（含 Manager 里）装的包会丢；
   r 和装完插件后的重启只是 `docker restart`，包还在。容器用 `--stop-signal SIGINT`，ComfyUI 收到后正常退出，
   不用等 Docker 默认的 10 秒超时（这个设置在建容器时生效，老容器要菜单 R 或 2 重建一次）。

7. **升级部署套件**（换了新的 deploy.sh / Dockerfile）后先跑菜单 2：安装和更新会重建镜像，
   r / R / 4 / 5 / 6 / 9 不会，会继续用旧镜像。只换了套件、不想拉 ComfyUI 新代码时选菜单 1。旧镜像重建后自动删除。
   **只改了自带节点 / 工作流 / 素材**（没动 Dockerfile 和依赖）：在套件目录 `git pull`，然后 `bash deploy.sh --sync`（菜单 s）：
   `pro-*` 节点同步成仓库版本（旧版先备份到 `data/custom_nodes-旧版备份-时间/`），有变化才 `docker restart`（有任务在跑会先问）；
   工作流只补新增的，和仓库不同的只提示，要换成仓库版本用 `bash deploy.sh --refresh-workflows`（菜单 w，旧文件先备份到 `data/user/default/workflows-旧版备份-时间/`，
   你在网页里自己存的工作流不碰，仓库里已经没有的旧工作流只列出来、不删）。重建容器（菜单 1 / R / 2 / 4 / 5 / 9 / 12）也会做同样的节点同步。
   同步后网页要强制刷新（⌘⇧R / Ctrl+Shift+R），否则浏览器里还是旧的节点列表，会提示「缺失节点包」。

8. **更新前预览、失败自动退回、可以回到上次更新前**：
   - 菜单 2 先 `git fetch`（不合并），列出每个仓库主线上的新提交，并标出风险：插件依赖变了；本地改过的文件上游也改了
     （插件可能冲突，冲突时用上游版本、改动进 stash；源码 pull 必然失败，要先 stash 或提交）；本地和上游分叉；源码不在分支上；
     fetch 失败（显示真实原因）。有风险默认不继续。
   - 构建镜像失败时，旧容器还在跑，脚本把源码和插件退回更新前的 commit，服务仍是旧版。
   - 构建成功但运行才出问题（插件加载失败、前端回归）：菜单 12 回到上次更新前，按旧依赖重建镜像。
     只记最近一次真正拉到新代码的更新（`.last-update`，构建前就写好，Ctrl+C 中断也能退）。回退时如果构建失败，
     仓库会恢复到回退前（和还在跑的容器一致），网络好了再选 12。新版如果升级过数据库，旧版日志里可能报 DB 错误，
     工作流不受影响；回退前会把 `comfyui.db.bkp` 另存为 `data/user/comfyui.db.pre-update`（旧版启动时会覆盖并删掉 .bkp）。

## 内置工作流、自带节点和补丁

**Key 存哪**：模板里不带 Key。每个 Relay API Settings 节点按**节点 id** 在服务器 `relay_config.json` 里取 Key（首次也可以在节点的 apikey 填一次，之后记住）：
`1` 网关（gemini-image 出图 / 文字）、`11` geminiweb（视频、Gemini 音乐）、`21` Suno、`31` 阿里百炼（DashScope，国内版 `dashscope.aliyuncs.com`）。
工作流里的 Key 节点默认**折叠成一条黄色小条**，标题写明是哪个 Key（如「Key：阿里（填一次）」）：第一次用点标题左边的小圆点（或选中后按 Alt+C）展开，填一次 apikey，之后服务器记住，不用再展开。

**老安装升级**：以前铺进去的是 26 个旧编号的工作流（含平铺文件和 1-一条龙 … 6-视频 六个子目录），后来是 11 个 `NN-名称.json`，现在是 11 个 `NN-名称.app.json`（1-图片 / 2-文案与配音 / 3-视频）。
部署只会铺入不存在的文件，旧文件不会自动删，会和新的并存（侧栏里同名两份）：`bash deploy.sh --refresh-workflows` 会把 11 个新的补齐，并把「不在仓库里」的旧工作流列出来，确认是旧版内置的（旧编号的，或同名但少了 `.app` 的）就先备份再移走（在网页里改过的先另存）。旧→新对照见下表「合并自」。

**怎么用（所有工作流都一样）**：每个工作流都是一个**应用**（ComfyUI 的 App 模式）：打开就是应用界面——**右栏**是要填的几项（模式 / 一句话需求 / 上传的素材 / 少量参数），
点底部**「运行」**，**结果显示在中间**：图片 / 视频 / 音频直接看，AI 写的提示词、文案、出错信息是文字。中间默认显示**最后出来的那一条**（成功时一般是图 / 视频 / 音频，
因为 AI 写的提示词在生成之前就存好了；06 的文案最后出，会排在图片前面），其余在下面的缩略图条里点开；还有「重新运行 / 复用参数 / 下载」。
- **「模式」**（中文下拉）选引擎 / 选做法；**「一句话需求」**填想要什么（`pro-ali` 的「阿里 写提示词」把它扩写成完整提示词，写了什么在结果文字里能看到）。
  不同模式用到的节点不一样，**没选中的那一路根本不会运行**（不调接口、不花钱，也不会因为没填它的 Key 报错）；右栏控件名里写了「（XX 模式）」的就是这个意思。
- **出错**：生成类节点出错（网关 503、Suno 没配渠道……）时，中间显示「出错信息」，成功时不显示；节点直接报错的（没填 Key、阿里 422……）在右栏底部出现红色卡片，点「在图中显示错误」看详情。
- **想看节点 / 改右栏没有的参数（比例、模型……）**：左上角「应用 ▾」→「退出应用模式」，或按 **Alt+M**（Mac：**Option+M**，输入法切英文）在应用界面和节点图之间切换。
  官方把节点图界面里的「进入应用模式」菜单项藏在功能开关后面（自己部署的默认关），要先用快捷键进过一次应用模式，菜单里才会出现它。
- 左侧栏的「应用」标签列出这 16 个应用（它只列文件名以 `.app.json` 结尾的）。
- 文字结果会存在 `data/output/text/`（一次一个小 .txt），不需要可以定期清。

**节点图里**（退出应用模式后）：画布最上面是两个带 ★ 的节点——**「★ 先选模式」**（中文下拉：选引擎 / 选做法）和**「★ 只填这里：一句话需求」**
（`pro-ali` 的「阿里 写提示词」：第一个框填需求，第二个框是扩写指令，一般不用改）。选好模式、填好一句话，点运行；节点标题里写了「只在 XX 模式用」的就是上面说的没选中就不运行。

**画布怎么看**：打开工作流直接对准最上面的绿色分组框「① 先填这里」，往下是灰色的「② 自动处理，不用管」，右下是蓝色的「③ 结果在这里」：
- **绿色节点**：要你选 / 填 / 上传的（模式、一句话需求、上传的图 / 视频 / 音频、要调的参数）；
- **灰色节点**：自动处理，不用管（想改出图比例、模型这类参数才动这里）；**黄色折叠小条**是 Key（见上）；
- **蓝色节点**：结果（图 / 视频 / 音频 / 文案）。relayapi 出错时不会让整个流程变红，错误信息显示在结果区的「状态」预览里，所以不要折叠它；折叠成一条的「应用界面 · …」小条是给应用界面用的文字结果（见下），不用管。

布局和颜色都由 `tools/gen_workflows.py` 里的 `tidy()` 按节点角色算出来（工作流函数里写的 pos 只当同一列里谁在上谁在下的排序依据），新增工作流不用手摆；
角色按节点类型判断，个别例外在各工作流函数里用 `g.in_ids` / `g.out_ids` / `g.auto_ids` 声明。

**应用界面的配置**：存在工作流 JSON 的 `extra.linearData`（`inputs`：右栏控件 `[节点 id, 控件名]`，按顺序从上到下；`outputs`：结果节点 id）和 `extra.linearMode`（`true` = 打开就是应用界面），
由 `tools/gen_workflows.py` 生成：`g.app_in(节点, 控件, 名字)` 登记右栏控件（同一个工作流里有两个「图像」上传、两个「比例」时必须起名，名字写进节点的 `inputs[].label`，节点图里这个控件也显示它；右栏里太长的名字会被截断，尽量 12 个字以内），
`g.app_out(节点)` 登记结果节点，`app_text(...)` 登记文字结果。**应用界面只显示文件类结果**（图片 / 视频 / 音频 / 文字文件）：预览节点（PreviewAny）返回的是裸字符串，应用界面不显示，
所以文字结果要经 `pro-flow` 的「应用界面：文字结果」节点（`ProAppText`）存成 `output/text/*.txt`；「出错信息」那几个设成只在出错时才存（relayapi 成功时的 `{"code": "success", ...}` 不显示）。
右栏登记的控件名写错，ComfyUI 只在控制台警告、右栏悄悄少一项，`tests/` 里会检查。应用界面默认显示最后出来的那一条，所以别把「和成片几乎同时出来的文字」登记成结果（11 的字幕文字就没登记，见 `tests/` 里的豁免说明）。

**多角色对白（13 / 14，`pro-ali` 的 `ProAliDialogue`）**：脚本每行写「角色：台词」（中英文冒号都行；「旁白：」或没写角色的行用旁白音色；括号里的动作提示（笑）不念；角色名比较时括号里的说明不算——角色表里写「小美（店员）」，台词里写「小美：」「小美（笑）：」都对得上；纯数字的名字可以用，「10:30 开始」这种时间开头的行不会被当成角色），角色表最多 4 个（名字 + 音色，名字是单行输入框），音色下拉里每个音色后面写着性别和特点（概括自官方《Qwen-TTS 音色列表》；Ebona 官方表没收录，不知道风格）。每句台词合成一次（计费请求只发一次、不重试），按真实时长拼起来，所以字幕时间是精确的（不靠停顿检测），字幕前面写角色名（可关）；已合成的句子存在容器的临时目录里，改几句再运行只重做改过的，中途失败（网络断了）重跑也不会把前面付过费的句子再付一遍。台词里出现角色表里没有的名字直接报错、不猜（猜错了会用错声音）。一次最多 40 句 / 1500 字。14 的上传视频模式里，**对白比视频长的部分会在视频结束处被截掉**（每秒大约念 4~5 个字，Veo 视频约 10 秒，对白控制在 40 个字以内）；图片轮播模式视频时长自动跟对白走。工作台里 AI 会按你的要求写对白、按性别 / 年龄给角色挑音色；08 / 10 / 11 / 12 的「配音音色」下拉在工作台里也会显示同样的性别 / 特点说明（值仍是纯名字）。

**商品抠图与图层（15 / 16，`pro-image` 的 `ProMatte` / `ProSaveCutout` / `ProLayerCompose`）**：想保持商品原样（形状、颜色、包装上的字一个像素都不能变）只换背景 / 调位置大小 / 加阴影，用这两步：先 15 抠成透明底，再 16 放到背景上；要标签再接 05。工作台里直接说「把这张图抠出来放到米色背景上，加个限时三天的标签」，AI 会排成 抠图 → 图层合成 → 图片后处理；改背景或位置只重做合成那一步（秒出）。想让 AI 把商品和场景的光影融在一起（可以接受商品被重画一点），仍然用 03。**抠图怎么做的**：`matte_engine.py` 用 onnxruntime 在**单独的小进程**里跑 u2net 一类的 ONNX 小模型（预处理 / 后处理和 rembg 一致，实测和 rembg 的输出逐像素相差不超过 1；没装 rembg，它连带 numba / scikit-image 等一大堆，服务器内存只有 4GB），跑完进程退出、内存全部还给系统（实测 u2net 约 560MB 峰值，一张 2.5~6 秒；u2netp 约一半内存、1~2 秒），内存真不够时被杀的是这个小进程（它把自己的 oom 分数调高了），ComfyUI 本身不受影响，节点只报一句人话。模型文件第一次用时从 rembg 的发布页下载到 `models/rembg/`（`PRO_MATTE_MODELS` 可以换地方；下载先到临时文件、校验 md5 再改名；下不了会写清楚去哪下、放哪里）。**镜像里要有 onnxruntime**：已经写进 Dockerfile（全新安装的机器自动就有），否则 15 会提示「容器里没有 onnxruntime」。**已经在跑的机器不要为了它走 `--update`**：`--update` 会连 ComfyUI 源码和插件一起 git pull，再从头重建镜像；构建缓存没了的话，实测会把约 30 个依赖悄悄升到最新（`av` 18→19、`huggingface_hub` 1→2、`torch` 2.14.0→2.14.1、`pydantic`、`google-genai`……），改动面比这次需要的大得多。只加它、别的包一个都不变的做法：`docker tag comfyui:local comfyui:pre-onnx`（回退用）→ `printf 'FROM comfyui:local\nRUN pip install onnxruntime\n' | docker build -t comfyui:local -` → 菜单 `R`（重建容器；镜像已经存在就不会再构建）。**已知局限**：背景干净的商品照抠得最准；透明 / 反光 / 毛发这类边缘复杂的商品不会很完美；画面里有好几件东西时 u2net 只留最主要的一个（「更利落」会把别的也留下）；分层 PNG 是各层单独的文件，不是一个带图层的 PSD（ComfyUI 自带的应用界面里「同时存分层 PNG」打开后，主图位置显示的是最后保存的那一层，要看合成图请到工作台或输出文件夹）；画布单边最大 4096 像素（「输出清晰度」最大 2048）；16 里放进来的商品必须是透明底的（整张都不透明的照片会报错并提示先抠图，不会悄悄贴成一个方块）。

**AI 写提示词**（01 / 02 / 03 / 04 / 06 / 07 / 08 / 09 / 10 / 12 带「★ 只填这里」）：阿里 `qwen3.8-flash`（07 用 omni），Settings 节点 id 31，和其他阿里工作流共用 Key。
出错（没填 Key、网络断了）会直接报红，不会拿空提示词去出图；连接失败自动重试一次。每类用不同的扩写指令（生图 / 生视频 / 改图 / 场景合成 / 配乐 / 音色描述 / 写文案 / 翻译），
改图类把「商品保持原样」写死在指令里；海报不让 AI 写整段，只让它填 4 个字段。没有跳过开关：想用自己写好的完整提示词，直接填进「一句话需求」，模型会忠于原意只做补充。
没有提示词可写的（05 后处理、11 视频成片、13 多角色配音、14 对白成片、15 商品抠图、16 图层合成）不带。

**模式节点怎么工作**（`pro-flow`）：「模式」节点输出「走第几路」和随模式变化的开关 / 指令文字；「选择分支」按它取一路输出、「开关门」关着时输出空——
它们都是**惰性**的（ComfyUI 的 lazy 机制），没选中的上游不会被执行。要点：保存 / 预览这类输出节点不能直接接在某一路的节点上（ComfyUI 会为了它强制执行那一路），
要经过选择分支再接；`ProVideoDub` 是唯一允许直接作为最终输出的节点。relayapi 的生成节点失败时媒体输出被 `ExecutionBlocker` 拦住、错误只在 `response` 里，所以「取媒体」和「取状态」是两个选择分支（合在一起状态也会被拦，失败时界面「成功」却什么都没有）。`tests/` 里有一个惰性执行模拟器，会逐个模式检查「没选中的引擎 / 设计 / 克隆 / 轮播不会运行」。

每个 relayapi / 阿里工作流都接了「状态」预览：relayapi 节点出错时不抛异常（作者为批量流程这样设计），错误只在 `response` 输出里，不接出来就会显示「成功」却没有结果；应用界面里对应的是「出错信息」（只在出错时出现）。

**批量跑**：`python3 tools/batch_run.py <工作流.app.json> <表.csv> [--server http://127.0.0.1:8188] [--timeout 600]`。表头写 `节点ID:控件名`（如 `2:image`、`6:text1`，节点 id 看画布左上角/节点属性；`tools/batch_example.csv` 是 05 图片后处理「贴促销标签」的例子），值是本地图片路径会先上传，`out` 列是本行输出前缀（默认 `batch/行号`，落在 `data/output/batch/`）。逐行串行提交，已成功的行记在 `<表>.done`，中断后重跑自动跳过；随机种子每行自动换。转换器已对旧的 24 个模板逐个和前端导出的 API 格式比对一致。**合并后的工作流选模式**：加一列 `77:mode`，值写模式的完整中文名（如 `阿里 qwen-image（2K，中文字准）`）。

**内存与合成**：机器只有约 4GB 内存。ComfyUI 自带的 `GetVideoComponents` / `CreateVideo` 会把整段视频解码成浮点张量（10 秒 720p ≈ 2.6GB），实测**会被系统 OOM 杀掉**，所以视频合成一律用 `pro-video`（PyAV 复制画面包，内存几乎为零）。**烧字幕要中文字体**：容器里没有，`deploy.sh` 启动容器时会把宿主机的 `fonts-noto-cjk`（`/usr/share/fonts/opentype/noto`）只读挂进去；宿主机没装就先 `apt install fonts-noto-cjk`，再用菜单 R 重建容器，否则烧字幕会报「需要中文字体」。`LoadVideo` / `LoadAudio` 只能选 `data/input/` 里的文件：用节点上的上传按钮，或把 04/20 出的视频从 `data/output/` 拷到 `data/input/`。

**阿里接口**：服务器在德国、阿里在北京，链路偶尔慢：大图（1MB 的 PNG）上传曾超过 180 秒，缩到 768 后约 10 秒。阿里节点的超时是 生图 200 秒 / 配音 90 秒 / 下载 60 秒，**计费请求（生图 / 改图 / 配音 / 听写 / 音色）只发一次、不重试**（重试会重复计费）。key 只会发往 `*.aliyuncs.com`。
**连接阶段单独处理**：这条线路实测握手偶尔卡 10~25 秒后被重置，所以发请求前先对同一个主机发一个**免费的 HEAD**（不带 Key）把 TCP + TLS 连接建好，建不好就重试（每次 3 秒超时，最多 4 次），请求再走这条连好的连接——这时什么都没发出去，重试不会重复计费；4 次都连不上就报「连不上……请求没有发出，不会计费」。请求发出去之后等回复超时，报错会写明「请求已经发出，可能已计费，先别连着重跑」。下载生成结果是 GET，失败自动重试（最多 3 次，4xx 除外）；写提示词的文字请求几乎不花钱，连不上（含超时）整个请求再试一次。按量计费，2K 大图和 `qwen-image-3.0` 较贵。

**阿里未开通的产品**：MiniMax 配音（`MiniMax/speech-2.8-*`）在模型列表里能看到，但调用返回「产品未开通」，要在百炼控制台开通后才能用；`qwen-mt` 翻译需要另外的参数格式，用通用模型翻译已经够好。阿里听写（ASR）实测 6 秒音频从这台服务器约 20 秒（上传慢）。

**已知限制**：gemini-image 实际只出约 1K（要大图用 01 / 02 的阿里引擎，或 05 放大）；服务器只有 2 核，构建镜像时出图会 503 过载；官方「合作方」节点（走 Comfy 积分）填不了自己的 key，不可用；阿里 key 里没有视频模型；**图生视频（12）的参考图没能证实真的用上了**：12 先让 AI 看图、把图里的商品 / 背景 / 光线写进视频提示词，同时把图当参考图发给 Veo（relayapi 的 `input_reference`），但这条 geminiweb 网关有没有把它传给 Veo 没证实（实测：描述了画面的提示词能出片；没有主体的提示词（「镜头缓慢推近，物体轻轻摆动」）连试两次 Google 都没触发视频工具；网关程序里搜不到 `input_reference`），所以视频和图「相近」但不保证一模一样，要像素级贴合得换支持参考图的视频渠道。Veo 的比例 / 时长设置网关照不照办也没验证（实测默认设置出来都是 1280×720、约 10 秒），放在高级设置里；网关自己的说明里 Veo 约一半会失败，失败了再运行一次；没有抠图/透明底；自定义音色 id 存在阿里账号里，用「阿里 音色管理」节点列出/删除（画布的「音色管理」页就是调它）；11 的图片轮播只有缓慢推拉和淡入淡出两种效果。

## AI 工作台（大窗口，`pro-chat`）

网页打开默认就是**工作台**（盖在 ComfyUI 上面的大窗口）：左边聊天，右边是**方案**（一步一张卡）和**素材库**。
说一句话（可以附商品图 / 视频 / 音频），AI 排出**一步或几步**（每步 = 一个应用：出图 → 出视频 → 配音 → 成片……），选好模式、写好设置；
你在右边每一步里改设置，点「运行全部」一键跑完，也可以只跑某一步。**前一步做出来的图 / 视频 / 音频自动放进素材库，下一步直接拿来用**，也可以说「用第二张图出视频」「用素材 3 做视频」。
16 个应用和节点图都还在后面：右上角「回到节点图 / 应用」关掉工作台，左边缘的蓝色竖条（或左栏的「AI 工作台」图标）再打开；开 / 关会记在浏览器里，默认打开。

- **方案**：最多 6 步，每步一张卡：模式、文字、文件、常用设置直接显示，「高级设置」折叠；设置有五种控件——文字框、下拉、数字（滑块 + 数字框，按节点定义的范围限制）、开关、文件（下拉里选前面某一步的结果 / 素材库里的 / 当场「上传…」）。
  改过的设置高亮、带「↺ 恢复默认」；不改的不会写进方案（保持工作流里的默认值）。每步的状态：还没运行 / 运行中 / 已完成 / **要重跑**（设置改过了，或它用的前面步骤重新跑过了）/ 没成功 / 已停止。
  不用 AI 也能搭：顶部「＋ 添加一步…」从应用目录里选。用 Veo 等有额度 / 费用的步骤，方案顶部会提醒（`extra.appCost`）；有「必填」文件（03 / 04 / 05 / 06 / 12 的商品图 / 参考图）没给时，这一步和「运行全部」都不让点，并写明还缺什么；有的文件只在某个模式必填（16 的背景图：「放到背景图上」模式必填、「放到纯色背景上」不要；02 / 03 / 07 / 08 / 11 / 14 的上传图片 / 视频 / 音频同理），「（必填）」标记和能不能运行都跟着所选的模式走，换模式马上变。
- **运行**：每一步是一次独立的运行：后端把应用的工作流转成 API 格式（`custom-nodes/pro-chat/api_convert.py`，和 `tools/batch_run.py` 是同一份）、填进这一步的值、`seed` 随机、提交到本机队列，前端等 `/history` 出结果；
  结果里的图 / 视频 / 音频经 `POST /pro/stage` 从输出目录复制进 `input/助手/`（用内容哈希命名，同样的内容只存一份），登记成素材库里的下一个编号，后面的步骤就能当 `LoadImage` / `LoadVideo` / `LoadAudio` 的输入。
  **改哪步只重跑哪步**：「运行全部」只跑还没跑的、要重跑的，以及因为前面步骤重跑而过期的；AI 改方案时，设置没变的步骤保留原来的结果。中途失败 / 停止就停下，后面的不动；运行中刷新网页会接着等已经提交的那一步（视频要几分钟，不用守着），
  提交到一半刷新也不会重复提交：每次运行带一个 `run_id`（先存档再提交），刷新后用同一个 `run_id` 再提交，后端同一个 `run_id` 只会真的提交给 ComfyUI 一次（拿到的是上次的 `prompt_id`；服务重启后这个记录就没了）；网络断了这类「请求没发出去 / 回复没收到」的失败也会用同一个 `run_id` 自动重试 3 次，不算这一步失败；3 次都没拿到回复时这一步显示没成功（不知道服务器有没有收到），再点「再试一次」会沿用这个 `run_id`（设置没改的话，服务器收到过就直接接上那一次，结果里会写明，不会重复提交；改了设置就是新的一次）。
  关掉网页后，已经提交的这一步照常跑完，「运行全部」里后面的步骤要等你重新打开页面接着跑。**同一个浏览器开两个标签页**（包括「复制标签页」复制出来的）时只有一个能运行 / 续跑，另一个只显示进度：运行锁优先用浏览器的 Web Locks（独占，运行的标签页关了 / 崩了浏览器自己放，另一个标签页几秒内接手，并按存档里的模式把「运行全部」接着跑完）；页面不是 https / localhost、用不了 Web Locks 时退回 `localStorage` 里的运行记录（每 5 秒续一次、90 秒没续就算死了；记录被别的标签页抢走后，这里跑完当前这一步就停）；运行中和等 AI 回复时方案都不能改（运行中不能发消息、不能删 / 打开别的步骤；等回复时运行 / 删除 / 设置控件都锁住，不然回复一到整个方案会被换掉）。点「停止」时如果还在提交，拿到 `prompt_id` 后立刻中断，并把它从队列里删掉。
  ComfyUI 只是部分校验没通过时（有的输出分支不会运行）仍会照常排队，工作台会在这一步的结果里用黄字写出为什么。「在应用里打开」把这一步载入成一个新标签页并填好设置（会关掉工作台），方便接着手动调。
- **素材库**：编号从 1 开始只增不减（清空全部才重置），同样内容的文件不重复占编号，最多 200 个；右下角缩略图点一下，把「素材 3」放进输入框。聊天里附的文件（粘贴 / 拖进来 / 点「附件」，图片 20MB、视频 150MB、音频 50MB）和每步的结果都在里面；
  素材一律放 `data/input/助手/`，运行 / 看图只认这个目录里的文件（按路径分段拒绝 `..` / 空段 / 反斜杠，符号链接逃出这个目录的拒绝，文件名里有两个点没问题），**扩展名要和控件要的类型对得上**（图片放不进视频控件）。
  `/pro/stage` 只认输出目录里、图片 / 视频 / 音频扩展名、不超过 300MB 的文件；每次重跑都会产出新文件，所以素材目录会慢慢变大，不用的可以直接删 `data/input/助手/` 里的文件（工作台里对应的素材会显示「文件已经不存在」）。
- **怎么选应用**：后端每次从服务器上的工作流文件现读「应用目录」（`workflows` 里所有 `*.app.json`：`extra.linearData` 的右栏控件 + 节点定义里的类型 / 范围 / 选项 + 工作流里存的默认值），
  连同每个应用的用途描述（`extra.appDescription`）、费用 / 注意（`extra.appCost`）、常用设置（`extra.appExtra`）、高级设置（`extra.appAdvanced`）、必填文件（`extra.appRequired`；只在某些模式必填的写成 `[节点, 控件, [模式序号…]]`，`g.app_required(节点, 控件, modes=[…])`）一起给模型，这些都在 `tools/gen_workflows.py` 里用 `g.app_desc` / `g.app_cost` / `g.app_extra` / `g.app_required` 登记；
  `appExtra` / `appAdvanced` **只给工作台用，不进 ComfyUI 的应用右栏**（应用界面保持原样简洁）；下拉可以只开放节点里的几项（比如 Veo 只开放 16:9 / 9:16、4 / 6 / 8 秒）。你自己存的 `*.app.json` 也会进目录。
  模型编出来的应用 / 模式 / 字段 / 素材编号 / 步骤引用后端一律丢掉（`catalog.clean_selection` + `chat.make_plan`）：数字收回范围、开关只认开 / 关、下拉必须是选项原文、「步骤N」只能引用排在前面且真的产出该类型文件的步骤；价格、日期、文案原文按用户说的保留。
  方案里漏了必填文件（比如改商品图却没有图）时，后端会让模型重写一次（改用不需要图的应用，或先请用户上传），还不行就带着黄字提示给你。选项原值是数字的下拉（11 的轮播帧率 24 / 30、清晰度 720 / 1080）：界面和方案里是文字，运行时才转回数字交给 ComfyUI（它的下拉是严格比对的，文字 "30" 不等于数字 30）。
- **模型和 Key**：文字用阿里 `qwen3.7-plus`（`qwen3.8-flash` 试过：改方案时会改错 / 丢信息），带新图的那一轮用 `qwen3.8-omni-flash`；Key 是 Settings 节点 id 31 的那个（服务器上读 `relay_config.json`，只发往 `dashscope.aliyuncs.com`，不会回给网页）；
  没填过会在对话里提示去哪填。每轮请求带整个应用目录（约 1.2 万字）和最近 40 个素材的清单，文字请求几乎不花钱。
  **到阿里的线路不稳**（德国 → 北京）：连接阶段 6 秒超时、自动重连（最多 3 次）；请求 8 秒没回就并发再发一个（最多同时 3 个），谁先回用谁；等回复最长 60 秒；输入框上方显示已等了多久。偶尔报「阿里这次回得太慢」，再发一次即可。
- **「要重跑」怎么判断**：每一步记着上次跑完时的设置（`ran`：应用 / 模式 / 改过的设置 / 素材库里的文件，加上它用的前面步骤的序号和第几个结果）和前面步骤当时跑过几次（`usedRuns`）。设置变了、或前面的步骤重新跑过，就标「要重跑」。AI 改方案或你删 / 加步骤时，按「应用、设置、引用的前面步骤是不是同一个」认出哪些步骤没变（序号变了也认得），没变的保留结果；删掉前面的步骤，后面已完成的步骤引用的序号会跟着换，不会被误判成要重跑。
- **对话和方案**只存在这个浏览器里（localStorage `proChat.v2`：最近 60 条消息、素材库清单、当前方案和每步的结果；开 / 关状态 `proChat.ui`），「清空全部」清掉；换浏览器 / 清缓存就没了，服务器不存对话（素材文件在服务器 `input/助手/`）。旧版（`proChat.v1`）的聊天记录不迁移。
- **接口**（前端用 `/api/pro/...`）：`POST /pro/chat`（对话 → 方案）、`POST /pro/run`（运行一步）、`POST /pro/stage`（把输出目录里的结果放进素材库）、`GET /pro/catalog`（应用目录，手动加步骤用）。
- **限制**：只能选目录里有的应用（做不了的会直说）；模型偶尔会追问细节、选错模式或漏了必填素材（会有黄字提示），看右边的方案再点运行，不对就在卡片里改，或接着说。一个方案最多 6 步，一次只跑一个。
  聊天 / 工作台里上传的素材在 `input/助手/` 子目录里，ComfyUI 的图片下拉不列子目录：「在应用里打开」载入的标签页里能正常显示和运行，但**刷新网页后**那个标签页会提示「缺少媒体输入」，重新点一次「在应用里打开」即可。
- **改了工作流怎么办**：目录是现读的，改完 `*.app.json` 不用重启；新增 / 改了用途描述、设置就改 `tools/gen_workflows.py` 再重新生成（有测试检查每个应用都有描述、登记的每个设置都真的存在、不会被悄悄跳过）。
  `pro-chat` 的 Python 代码要重启容器才生效（和其他自带节点一样，`deploy.sh --sync` 会处理）；前端脚本强制刷新网页（Windows：Ctrl+Shift+R）。

## 接反代 API

base_url 填 New API **根地址，不要带 `/v1`**（节点自己拼路径）：

| 模型 | 节点 | 填法 |
|---|---|---|
| gpt-image / grok-imagine-image | APIimage「OpenAI Image Generate」 | `base_url: http://<宿主机IP>:13000`，模型名填 `custom_model` |
| gemini-image（走 chat） | relayapi「Relay API Settings」→「Relay Image Generator」 | `custom_api_base: http://<宿主机IP>:13000`，`api_format: v1/chat/completions`，`task_type: image`，`custom_model` 填模型名 |
| 豆包 Seedream | APIimage「ModelArk Image Generate」 | 只有它要带 `/v1`：`http://<宿主机IP>:13000/v1` |

- 改图：Load Image 接 OpenAI 节点的 `image1`（多图再接 `image2`/`image3`），局部重绘把 MASK 接 `mask`，走 `/v1/images/edits`。
- 容器里的 `127.0.0.1` 是容器自己，填宿主机内网 IP 或 `172.17.0.1`（New API 要监听 0.0.0.0）。填之前先用菜单 11 从容器里测一遍地址和令牌。

## 让网页（如画布）跨域直连

浏览器带 `Authorization` 头访问会先发预检 `OPTIONS`，而 `basic_auth` 会把它回 401；`basic_auth` 在 Caddy 里排在 `handle` 之前，所以要把认证和反代包进 `handle`，预检单独放行。站点片段（`<画布域名>` 换成实际来源，`/ws` 不要求认证）：

```
<ComfyUI 域名> {
	@preflight method OPTIONS
	handle @preflight {
		header Access-Control-Allow-Origin "https://<画布域名>"
		header Access-Control-Allow-Headers "Authorization, Content-Type"
		header Access-Control-Allow-Methods "GET, POST, OPTIONS"
		header Access-Control-Max-Age 86400
		respond 204
	}
	header Access-Control-Allow-Origin "https://<画布域名>"
	handle {
		@needauth not path /ws /ws/*
		basic_auth @needauth {
			<账号> <密码哈希>
		}
		reverse_proxy 127.0.0.1:8188
	}
}
```

改前先备份，`caddy validate` 通过再 `systemctl reload caddy`。自测：`curl -si -X OPTIONS https://<ComfyUI 域名>/prompt -H "Origin: https://<画布域名>" -H "Access-Control-Request-Method: POST"` 应返回 204 且带 `access-control-allow-origin`。

## HTTPS + 访问密码（共享机组特殊处理）

这台服务器 80/443 被香水商城 Caddy 容器占用，不要另装 Caddy。菜单 5 会：

1. 问域名、用户名和密码（不回显，输两遍），用 `perfume-shop-caddy-1` 生成 bcrypt 哈希，打印要追加到香水商城 Caddyfile 的站点：
   ```
   comfy.你的域名 {
       basic_auth {
           admin <哈希>
       }
       reverse_proxy 172.18.0.1:8188
   }
   ```
   然后 `docker exec perfume-shop-caddy-1 caddy reload --config /etc/caddy/Caddyfile`（Caddy 2.8 以前写 `basicauth`）。
   脚本不会改香水商城的 Caddyfile，要你自己贴进去。
2. 自检（只读）：检查 Caddy 容器的网关是不是 `172.18.0.1`，并在 Caddy 容器里访问 `172.18.0.1:端口`；填了域名、贴好站点后，
   再从本机测一次域名：401 = 密码生效，200 = 免密能访问（设了密码却 200 就是没生效）。Caddy 访问不到时，改绑默认选「否」。
3. 问是否把端口改绑 `172.18.0.1`（`-p 172.18.0.1:8188:8188`）。改了之后公网 `http://服务器IP:8188` 直连不通，只能走域名 + 密码；
   再进菜单 5 可以改回所有网卡。注意这只挡公网：本机进程和本机其他容器（包括香水商城的）仍能免密访问，所以 ComfyUI 仍要用单独的限额令牌。
   香水商城网络没起来（172.18.0.1 不在本机）时，更新 / 重建 / 改端口 / 恢复都会先停下，不拉代码、不删旧容器；
   已改绑时进菜单 5 第一步就能改回所有网卡。容器已经没了、菜单进不去时，把 `.install.conf` 里的 bind 改成 `bind=""` 再跑。
   菜单 4 换端口后要同步改 Caddyfile 里的 `reverse_proxy`。

Safari / iPhone 上如果看不到出图进度和结果（WebKit 的 WebSocket 不带 basic auth 凭据），把 `/ws` 排除在鉴权外：
```
comfy.你的域名 {
    @auth not path /ws
    basic_auth @auth {
        admin <哈希>
    }
    reverse_proxy 172.18.0.1:8188
}
```
`/ws` 只推送队列状态和进度，不能提交任务，也读不到 key。Chrome / Firefox 不需要这样改。
